# แผน: โหมดลองเล่น (Sandbox) — ลองกดได้โดยไม่แตะข้อมูลจริง

สถานะ: **ร่างให้เจ้าของโปรเจกต์ตัดสิน — ยังไม่ได้เขียนโค้ดสักบรรทัด**
ที่มา: `docs/next-prompts.md` ข้อ 4 · แรงบันดาลใจจาก My Clinic @ DTMU ที่มี `/mc/sandbox/` = แอปทั้งชุดอีกสำเนา ข้อมูลปลอม แถบแดงบนสุด

## ปัญหาเป็นภาษาคน

ทุกวันนี้เวลามีคนอยากลองแอป (นักศึกษาใหม่ · อาจารย์ที่เพิ่งได้ยินชื่อ · ตอนสอนวิธีใช้หน้าห้อง) เขาไม่มีที่ปลอดภัยให้กดเล่น
ถ้าเข้าเว็บนำร่อง https://prostho-tracker.vercel.app ทุกปุ่มที่กดคือของจริง — เคสที่สร้างเล่นจะไปนอนปนกับเคสผู้ป่วยจริง
และที่อันตรายกว่านั้นคือ **บัญชี `demo@…` บนเซิร์ฟเวอร์จริงยังมีสิทธิ์อาจารย์ เห็นผู้ป่วยทุกคนของทุกกลุ่ม** (`docs/status.md` ข้อ 3)
บัญชีนี้ถูกทำไว้ตอนยังไม่มีข้อมูลจริง วันนี้มันคือ "กุญแจสำรองที่ไม่มีใครเป็นเจ้าของ" — เรื่องที่อยากเลิกให้ได้มากที่สุดคือข้อนี้

อีกด้านหนึ่ง: ของที่แอปกลัวที่สุดคือข้อมูลตัวอย่างไหลขึ้นเซิร์ฟเวอร์จริง เคยเกิดมาแล้ว (ผู้ป่วยจาก 2 → 1,143 คน · HN ขึ้นต้น `DEMO-`)
จนต้องตั้งกฎว่า `seedIfEmpty` / `ensureAlumniSeeded` **คืนทันทีเมื่อ `cloudEnabled`** (`src/data/seed.ts` · `CLAUDE.md` หัวข้อ "ข้อมูลตัวอย่างห้ามแตะเซิร์ฟเวอร์จริง")
โหมดลองเล่นจึงไม่ใช่แค่งานหน้าจอ — มันคือการเปิดทางให้ข้อมูลปลอมกับข้อมูลจริงอยู่ใกล้กันขึ้น ต้องเลือกวิธีที่กันชนหนาที่สุด

## ของที่มีอยู่แล้ววันนี้ (ตรวจจากโค้ดแล้ว)

- **เว็บเดโมสาธารณะ** https://monet666byte.github.io/prostho-tracker/ — build ด้วย `npm run build:pages`, deploy อัตโนมัติทุก push ขึ้น `main` (`.github/workflows/deploy.yml`)
  · `cloudEnabled` ถูก **ปิดตายตอน build** (`src/lib/cloud.ts → isPublicBuild`) ไม่ใช่แค่ "หวังว่าจะไม่มีกุญแจ" — ต่อให้เครื่องที่ build มี `.env.local` ก็ต่อเซิร์ฟเวอร์ไม่ได้
  · เข้าโดยเลือกบทบาท ไม่ต้องล็อกอิน · หน้า login มีป้ายเหลือง `DEMO · ข้อมูลสมมติทั้งหมด` (`src/routes/Login.tsx`) · มีปุ่ม "รีเซ็ตข้อมูล" ในแถบ DEMO
  · เจ้าของตัดสินแล้ว 18 ก.ย. ว่า**คงเว็บนี้ไว้** (`docs/status.md` ข้อ 6)
- **คนละโดเมน = คนละลิ้นชัก** — `github.io` กับ `vercel.app` เป็นคนละ origin ข้อมูลใน IndexedDB จึงแยกกันโดยตัวเบราว์เซอร์เอง ปนกันไม่ได้แม้อยากให้ปน
- แต่เว็บเดโมนี้ **ยังไม่ได้ถูกเรียกว่า "โหมดลองเล่น"** ในแอปจริง ไม่มีลิงก์ไปหาจากเว็บนำร่อง และป้ายเตือนมีแค่หน้า login (เข้าไปแล้วไม่มีแถบบอกตลอดเวลา)

## ทางเลือก

### ก. ใช้เว็บเดโมที่มีอยู่เป็น Sandbox + ลิงก์จากแอปจริง (แนะนำ)

ประกาศให้เว็บ GitHub Pages เป็น "โหมดลองเล่น" อย่างเป็นทางการ แล้วทำสามอย่าง: เติมแถบเตือนถาวร · ทำทางเข้าจากแอปจริง · ถอดบัญชี `demo@…`

- **ผู้ใช้เห็นอะไร:** ในแอปจริง (หน้าตั้งค่า / หน้าช่วยเหลือ) มีปุ่ม "เปิดโหมดลองเล่น" ที่เปิดแท็บใหม่ไปเว็บเดโม ·
  พอถึงที่นั่นจะมี**แถบสีส้ม/แดงค้างบนสุดทุกหน้า** "ขณะนี้คุณกำลังใช้โหมดลองเล่น — ข้อมูลทั้งหมดเป็นของสมมติ ไม่ส่งไปที่ไหน" พร้อมปุ่มกลับไปแอปจริง
- **เสี่ยงปนกันแค่ไหน:** ต่ำที่สุดในสามทาง — คนละ build คนละโดเมน และ `cloudEnabled=false` แบบ build-time ไม่มีสวิตช์ให้พลาด
- **PDPA:** ไม่มีข้อมูลผู้ป่วยจริงอยู่ในเส้นทางนี้เลย · `DEMO_POLICY` ของโหมดไม่ต่อ cloud เปิดชื่อผู้ป่วยสมมติได้อยู่แล้ว (`src/data/pdpaSync.ts`)
- **งานที่ต้องทำ (เล็ก · ประมาณครึ่งวัน):** คอมโพเนนต์แถบใหม่ 1 ตัวใน `src/components/` (ขึ้นเฉพาะ `!cloudEnabled`) + จุดวางใน shell ทั้งสองฝั่ง
  (`components/student/Shell.tsx` · `components/teacher/TeacherShell.tsx`) + ปุ่มทางเข้าในแอปจริง + คู่คำแปลใน `src/lib/i18n.dict.ts` + แก้ README/`docs/status.md`
  ⚠️ แถบ `DemoBar` ปัจจุบันขึ้นเฉพาะจอกว้าง — แถบใหม่ต้องเห็นบนมือถือ 375px ด้วย จึงเป็นของคนละชิ้น
- **ค่าใช้จ่าย:** 0 บาท (GitHub Pages ฟรี · deploy อยู่แล้ว)
- **ใครดูแล:** ไม่มีใครเพิ่ม — มันคือ build เดียวกับที่ออกทุก push อยู่แล้ว
- **ข้อเสีย:** ลองได้แค่ "คนเดียวในเครื่องตัวเอง" — ทดสอบเรื่องที่ต้องมีหลายคนจริง (อาจารย์เห็นงานนักศึกษาที่เพิ่งกด · sync ข้ามเครื่อง · ล็อกอิน Google) ไม่ได้
  · ยังไม่ได้ตรวจว่าเปิดสองที่พร้อมกันบนเครื่องเดียว (เว็บนำร่อง + เดโม) แล้ว service worker/ไอคอน PWA จะสับสนไหม

### ข. โปรเจกต์ Supabase ที่สอง + Vercel ตัวที่สอง = Sandbox ของจริง

สำเนาเซิร์ฟเวอร์อีกชุด (`sandbox.…`) รัน migration ชุดเดียวกัน ใส่รายชื่อและเคสปลอม ใครก็ล็อกอินเข้าไปลองพร้อมกันได้จริง

- **ผู้ใช้เห็นอะไร:** เว็บหน้าตาเหมือนของจริงทุกอย่าง ต่างที่แถบแดงบนสุดกับที่อยู่เว็บ — ใกล้เคียง My Clinic ที่สุด
- **เสี่ยงปนกันแค่ไหน:** ข้อมูลคนละฐาน จึงปนกันไม่ได้ **แต่คนปนกันได้** — คนเปิดผิดเว็บแล้วกรอกเคสจริงลง sandbox (หรือกลับกัน) คือความเสี่ยงหลัก
  และต้องสร้างทางเขียนข้อมูลตัวอย่างลงฐาน cloud ขึ้นมาใหม่ ซึ่ง**สวนกับกฎข้อที่แพงที่สุดของโปรเจกต์** (`seed.ts` ถูกออกแบบให้ปฏิเสธโหมด cloud)
  ต้องเป็นสคริปต์แยกที่ปฏิเสธถ้า URL ปลายทางไม่ใช่ sandbox แบบเดียวกับที่ `restore.ts --yes` ปฏิเสธโปรเจกต์ผิดตัว
- **PDPA:** ตัวมันเองไม่มีข้อมูลจริง แต่เพิ่มพื้นที่ที่ต้องเฝ้า — ถ้ามีคนเผลอกรอกชื่อคนไข้จริงลงไป นั่นคือข้อมูลจริงในที่ที่ไม่มีใครดูแล
- **งานที่ต้องทำ (ใหญ่ · หลายวัน + งานประจำไม่จบ):** รัน `0003`–`0029` ทั้งชุดบนโปรเจกต์ใหม่ (ทุกวันนี้ยังรันด้วยมือ ไม่มีตารางบันทึกเวอร์ชัน) ·
  โปรเจกต์ Vercel ที่สอง + Environment Variables + `vercel.json` เดิมใช้ได้ · Google OAuth ต้องเพิ่ม redirect URL ของโดเมนใหม่ ·
  สคริปต์ใส่ข้อมูลตัวอย่าง · เพิ่มเอกสารใน `docs/dev-setup.md` · **และทุก migration ในอนาคตต้องรันสองรอบตลอดไป**
- **ค่าใช้จ่าย:** ยังไม่ได้ตรวจ — โปรเจกต์ Supabase ที่สองบนแผนฟรีมีเงื่อนไข (จำนวนโปรเจกต์ต่อองค์กร · การพักโปรเจกต์ที่ไม่มีคนใช้) ต้องเปิดดูหน้าราคาจริงก่อนตัดสิน
- **ใครดูแล:** ต้องมีคนรับผิดชอบเพิ่มหนึ่งคน — วันนี้แค่เซิร์ฟเวอร์เดียวยัง**ไม่มีเจ้าของงานสำรองข้อมูล** (`docs/status.md` ข้อ 4) ยังไม่มีสำเนาเลยตั้งแต่ 14 ก.ย.

### ค. สวิตช์ "โหมดลองเล่น" ในแอปจริง

ผู้ใช้กดปุ่มในแอปแล้วแอปสลับไปใช้ข้อมูลปลอมในเครื่อง โดยไม่ต้องเปลี่ยนเว็บ

- **ผู้ใช้เห็นอะไร:** สะดวกที่สุด อยู่หน้าเดิม กดกลับได้ทันที
- **เสี่ยงปนกันแค่ไหน:** **สูงที่สุด และเป็นความเสี่ยงชนิดที่เคยทำให้เสียหายจริงมาแล้ว** เพราะกันชนทุกชั้นวันนี้อ่านค่า `cloudEnabled` ที่ตัดสินตอน build:
  · ชื่อฐานข้อมูลในเครื่องถูกตั้งครั้งเดียวตอนโหลดโมดูล (`src/data/db.ts` บรรทัด 60 อ่าน `VITE_DEMO`) — สวิตช์ตอนรันจะใช้ลิ้นชักใบเดียวกับข้อมูลจริง
    ถ้าไม่รื้อให้ชื่อเปลี่ยนได้ + บังคับโหลดหน้าใหม่
  · `cloudEnabled` ถูกอ่านกระจายในไฟล์ฝั่งแอปกว่า 20 จุด (`repo.ts` · `cloudSync.ts` · `photoStore.ts` · `pdpaSync.ts` · `export.ts` · หน้าจออีกหลายหน้า)
    พลาดจุดเดียว = แถวปลอมเข้าคิวรอส่งแล้วขึ้นเซิร์ฟเวอร์จริงรอบถัดไป ซึ่งคือเหตุการณ์ผู้ป่วย 1,143 คนซ้ำอีกรอบ
- **PDPA:** ถ้าพลาด ผลคือข้อมูลปลอมปนฐานจริง (ต้องไล่ลบด้วย `supabase/remove-demo-rows.sql`) — กู้ได้แต่เสียความเชื่อถือกับภาค
- **งานที่ต้องทำ (กลาง–ใหญ่ · เสี่ยงสูง):** รื้อ `db.ts` ให้ชื่อฐานเป็นค่าที่เปลี่ยนได้ · ทำ `cloudEnabled` เป็นค่าที่อ่านตอนรัน · เทสต์ใหม่ทั้งชุด sync
- **ค่าใช้จ่าย:** 0 บาท · **ใครดูแล:** ตัวโค้ดเอง แต่หนี้ความซับซ้อนอยู่กับคนดูแลคนถัดไปตลอดไป

## ข้อเสนอ

**ทำ ก. ตอนนี้** แล้วเก็บ ข. ไว้พิจารณาตอนจะอบรมคนหมู่มากหรือส่งมอบให้ภาคดูแลเอง · **ไม่ทำ ค.**

เหตุผล: ของที่เราอยากได้จริงๆ มีสองอย่าง — ① ที่ปลอดภัยให้คนลองกด ② เลิกใช้บัญชี `demo@…` บนเซิร์ฟเวอร์จริง
ทาง ก. ให้ทั้งสองอย่างด้วยของที่มีอยู่แล้ว โดยไม่เพิ่มพื้นที่ที่ข้อมูลจริงจะหลุดออกไปได้เลยแม้แต่ทางเดียว
ส่วน ค. ให้ความสะดวกเพิ่มนิดเดียว แลกกับการรื้อกันชนที่กันเหตุการณ์แพงที่สุดที่โปรเจกต์นี้เคยเจอ — ไม่คุ้ม
และช่วงนี้เป็นช่วงนำร่องที่ยัง**ไม่มีสำเนาข้อมูลเลย** (`docs/status.md` ข้อ 4) ยังไม่ใช่เวลาที่จะเพิ่มเซิร์ฟเวอร์ให้ดูแล

## ถ้าอนุมัติ ก. — ลำดับงาน

1. **ถอดสิทธิ์ `demo@…` ก่อนงานหน้าจอ** (อันตรายวันนี้ ไม่ต้องรออะไร) — `npm run backup` ก่อน → เขียนไฟล์ SQL ใหม่ใน `supabase/`
   (ยังไม่มีไฟล์สำหรับบัญชีนี้โดยเฉพาะ · `remove-test-accounts.sql` รันไปแล้วแต่ไม่ครอบ `demo@…`) → `npm run test:rls` ผ่านก่อนส่งให้เจ้าของรัน →
   รันบนเซิร์ฟเวอร์ → `security-check.sql` → แก้ `docs/status.md` ข้อ 3
2. **mock แถบเตือนก่อนเขียนจริง** — ทำ 2 แบบให้เลือก (แถบเต็มความกว้างค้างบนสุด vs. แถบบาง + ชิปมุมจอ) ดูที่ **375px** และบน iPad ก่อนตัดสิน
   · ห้ามใช้เขียว/แดงชนกับสีสถานะผ่าน/เตือนที่จองไว้แล้ว — เลือกโทนจากค่าที่มีใน `src/styles/tokens.css`
3. **ลงโค้ดแถบ** (ขึ้นเฉพาะ `!cloudEnabled`) + ทุกข้อความห่อ `t()` และเพิ่มคู่คำแปลใน `src/lib/i18n.dict.ts`
4. **ทางเข้าจากแอปจริง** — ปุ่ม/ลิงก์ในหน้าตั้งค่าทั้งสองฝั่ง เปิดแท็บใหม่ พร้อมข้อความว่า "สิ่งที่ทำในนั้นไม่ถูกบันทึกที่ไหน"
5. **เทสต์ที่ต้องยังผ่าน:** `npm test` ทั้งชุด (โดยเฉพาะ `test:export` · `test:core` ที่ก๊อปไฟล์ต้นฉบับไปสับ import — เปลี่ยน import เมื่อไหร่ต้องไปแก้รายการ swap) ·
   `npm run build` และ `npm run build:pages` ต้องผ่านทั้งคู่ · ถ้าแตะ `vite/csp.ts` ให้รัน `test:csp-live`
6. **ลองจริงก่อนบอกว่าเสร็จ:** เปิดเว็บเดโมบนมือถือจริง กดจนจบเส้นทางเดโม 5 นาทีใน README แล้วดูว่าแถบไม่บังปุ่มไหน
7. แก้ README (หัวข้อ "ลองใช้") + `docs/status.md` ให้เรียกเว็บนี้ว่า "โหมดลองเล่น"

## คำถามที่ต้องการคำตอบจากเจ้าของ

1. เลือก ก / ข / ค (หรือ ก ตอนนี้แล้วค่อยพิจารณา ข ตามข้อเสนอ)
2. บัญชี `demo@…` — **ถอดสิทธิ์อาจารย์เฉยๆ** หรือ **ลบบัญชีทิ้ง** · และยังมีใครใช้บัญชีนี้อยู่ไหม (ต้องบอกเขาก่อน)
3. คำเรียกบนแถบ: "โหมดลองเล่น" / "โหมดทดลอง" / "Sandbox" — ภาคคุ้นคำไหนจาก My Clinic
4. ต้องการให้คนลอง **ล็อกอินด้วยบัญชีตัวเอง** ใน sandbox ไหม — ถ้าต้องการ ทาง ก. ทำไม่ได้ ต้องไปทาง ข.
5. เว็บลองเล่นจะให้ใครเข้าได้บ้าง — ใครก็ได้ (เป็นสาธารณะอยู่แล้ววันนี้) หรือเฉพาะคนในภาค (ถ้าเฉพาะใน ต้องคิดเรื่องด่านเพิ่ม ซึ่ง GitHub Pages ทำไม่ได้)
