# ผลสำรวจ: หลังอาจารย์ตรวจแล้ว นักศึกษายังแก้อะไรได้บ้าง (ถ้ายิง API ตรง)

สำรวจ 20 ก.ย. 2569 · **อ่านโค้ดและ migration อย่างเดียว ไม่ได้ยิงเซิร์ฟเวอร์จริง ไม่ได้แก้อะไร** · ที่มา: บทเรียนจาก My Clinic — ของที่ผ่านเส้นตายแล้วต้องนิ่ง
ยังไม่ได้เขียน migration — รอเจ้าของเลือกว่าจะล็อกข้อไหน

## สิ่งที่นักศึกษา **แตะไม่ได้อยู่แล้ว** (ไม่ต้องทำอะไร)

คะแนนรายคาบ (`checkins` — 0017/0020) · เงื่อนไขจบ `students.gates` (0009/0017) · ใบ Section II/III (0012 — อ่านอย่างเดียว) ·
ผลตรวจงาน `reviews` (0006) · แบบประเมินตนเองที่ส่งแล้ว (0010/0011/0028)

## ช่องที่ยังเปิด

| ช่อง / การกระทำ | ตอนนี้ | ควรเป็น | ความเสี่ยงถ้าล็อก (เครื่องออฟไลน์) |
|---|---|---|---|
| **ลบคาบที่ประเมินแล้ว** | บนเซิร์ฟเวอร์จริงวันนี้ **ยังทำได้** เพราะ `0027` ยังไม่รัน | รัน `0027` | ต่ำมาก — แอปรองรับแล้ว (ดึงแถวกลับ + บอกเหตุผล) |
| **ลบชิ้นงานที่มีใบประเมิน/ผลตรวจผูกอยู่** | เจ้าของลบได้ → ใบ Section II/III กับผลตรวจกลายเป็นแถวกำพร้า หายจากทุกหน้าจอ | บล็อกแบบเดียวกับ `checkin_delete_guard` (raise พร้อมข้อความไทยบอกให้ใช้ "คืนเคส" แทน) | ต่ำ — ทางลบรองรับการถูกปฏิเสธแล้ว |
| **แก้แถวประวัติ `updates`** (วันที่ทำ · ขั้น · ใครทำ) | เจ้าของแก้/ลบได้ | ช่องบอกตัวตนของแถวแก้ไม่ได้หลังสร้าง (raise) · **ยังต้องลบได้** เพราะลบชิ้นงานลบประวัติตาม | ต่ำ — แอปไม่เคยแก้ช่องพวกนี้หลังสร้าง |
| **`workpieces.proc_index` / `completed_at`** | เจ้าของตั้งเป็นเลขอะไรก็ได้ | **ห้ามบล็อก** — เก็บรอยค่าเก่า→ใหม่ฝั่งเซิร์ฟเวอร์แทน (แบบ `score_history`) | **สูง** — ปุ่ม "เลิกทำ" ลดเลขจริง · เครื่องออฟไลน์ส่ง 2→5 เป็นก้อนเดียว · ถ้า "คงค่าเดิมเงียบๆ" = step ที่กดตอนออฟไลน์หาย |
| `returned` · `minimum_requirement` · `counts_for_year` | ของนักศึกษาตามการออกแบบ | ปล่อยไว้จนกว่าภาคจะเคาะว่าเป็นคำตัดสินของอาจารย์ | ล็อกแล้วตัดความสามารถจริงทิ้ง |
| ลบรูปงาน · แก้ HN ผู้ป่วย | เจ้าของทำได้ | ปล่อยไว้ (PDPA: ลบง่ายดีกว่า · HN พิมพ์ผิดต้องแก้ได้) | — |
| ตาราง `submissions` / `issues` | เจ้าของแก้ `approved_by` เองได้ — **แต่ไม่มีโค้ดไหนใช้ตารางนี้** | ปิดให้เป็นของอาจารย์ก่อนมีใครทำหน้าจอมาใช้ | ศูนย์ |

หลักที่ได้: วิธี "คงค่าเดิมเงียบๆ" (0020) ใช้ได้เฉพาะช่องที่หน้าจอของบทบาทนั้น **ไม่เคยเขียนเลย** — จริงกับ `checkins` แต่ไม่จริงกับ `workpieces`
(ทุกช่องมาจากปุ่มที่นักศึกษากดเอง) ที่นั่นต้องใช้ raise หรือเก็บรอย ไม่งั้นงานออฟไลน์หายเงียบ

## ลำดับที่ควรทำ

> **สถานะ 20 ก.ย. 2569:** ข้อ 2, 3, 5 ทำแล้วใน `0030_teacher_evidence_locks.sql` · ข้อ 4 ทำแล้วใน `0031_workpiece_step_log.sql` · ทั้งสองไฟล์ **ยังไม่รันบนเซิร์ฟเวอร์** (เหมือนข้อ 1)

1. **รัน `0027` → `0028` → `0029`** — ปิดช่องใหญ่สุดได้ทันที ไม่ต้องเขียนอะไรใหม่
2. กันลบชิ้นงานที่มีหลักฐานของอาจารย์ผูกอยู่
3. ล็อกช่องบอกตัวตนของแถว `updates`
4. เก็บรอย `proc_index` / `completed_at` ฝั่งเซิร์ฟเวอร์ (ไม่บล็อก)
5. ปิด `submissions` / `issues`

## ของที่เจอระหว่างทาง

- **ปุ่ม "อนุมัติ/ตีกลับ" ไม่มีอยู่จริงในแอป** — `routes/teacher/Review.tsx` ส่งสถานะ `pending` เสมอ บันทึกได้แค่คอมเมนต์ · `workpieces.pending_qualification` ก็ไม่มีที่ไหนตั้งค่า
- **audit log ไม่ได้คุมการยิง API ตรง** — ทุกบรรทัดเขียนจากเครื่องผู้ใช้ คนที่ยิงตรงแค่ไม่เขียนแถวนั้น
- **นักศึกษาลบชิ้นงาน → แอปสั่งลบผลตรวจ (`reviews`) ตามไปด้วย แต่เซิร์ฟเวอร์ไม่ให้ (RLS กรองทิ้งเงียบ)** → ผลตรวจยังอยู่บนเซิร์ฟเวอร์แต่หายจากเครื่องนักศึกษา
  ไม่มีข้อมูลหาย (เปิดแอปรอบหน้าดึงกลับมา) แต่เป็นแถวกำพร้า — ข้อ 2 ข้างบนแก้เรื่องนี้ไปในตัว · **ยังไม่ได้ทดสอบจริง อนุมานจากกฎ**

## ยืนยันไม่ได้จากการอ่านอย่างเดียว

migration ไหนรันจริงบนเซิร์ฟเวอร์ (อ้างตาม `docs/status.md`) · บนเซิร์ฟเวอร์มี `reviews` ที่สถานะ approved/returned จากข้อมูลเก่าไหม · ช่องของ `workpieces`/`updates` ข้างบนยังไม่มีเทสต์ใน `test:rls` เฝ้า
